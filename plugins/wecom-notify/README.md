# 企业微信通知 · TgtoDrive 插件

为 **TgtoDrive** 补上企业微信（WeCom）通知能力：填写企业自建应用的凭据后，即可把任意文本、图文消息、markdown、文本卡片或模板卡片推送到成员、部门、标签或全体可见成员。

按企业微信官方接口实现：`GET /cgi-bin/gettoken` 与 `POST /cgi-bin/message/send`
（参考 <https://developer.work.weixin.qq.com/document>）。

- **插件 id**：`wecom-notify`
- **版本**：`1.0.0`
- **作者**：`a2695154202`
- **入口**：`plugin.py`
- **超时**：120 秒
- **依赖**：仅使用 Python 标准库 + 容器已安装的 `requests`（不可用时自动回退 `urllib`）。**不安装任何依赖。**
- **许可证**：GPL-3.0（与本仓库一致）

> ⚠️ **插件不含任何内置凭据。** 企业 ID、AgentId、Secret、Token、EncodingAESKey、白名单全部由你填写，代码里不存在示例值。

## 一、它能做什么

界面上「执行功能」只有下面 4 项：

| 功能（`func`） | 说明 |
| --- | --- |
| **发送测试消息（`test`）** | 内容**已内置**，无需填写：依次发出一条文本消息和一条卡片消息（**间隔 3 秒**，共两条通知），用来验证「配置 + 网络 + 收件人」整条链路。界面右上角有独立按钮 |
| 检查配置（`config`） | 逐项校验必填与格式，并真实获取一次 `access_token`，给出剩余有效期 |
| 查看发送历史（`history`） | 本地记录每次发送的时间、类型、收件人、结果与 msgid |
| **查看调用方法（`docs`）** | 输出「被其他插件调用」的参数表、示例与在线文档链接，界面右上角有独立按钮 |

界面上**不提供**的两项：

| 功能 | 为什么不在界面 |
| --- | --- |
| 发送消息（`send`） | 需要调用方传入正文，界面已无内容输入框；它是给其它插件调用的接口能力，用法见 [CALLING.md](CALLING.md) 与「查看调用方法」 |
| ~~查询应用可见范围成员（`users`）~~ | **已移除**（连同部门/成员查询代码）。收件人是否在可见范围内，现在由发送前的「投递校验」与返回值里的 `invaliduser` 覆盖 |

支持的消息类型（✅ 表示微信插件也能收到）：

- **文本 text** ✅ —— 正文上限 2048 字节，支持换行与 `<a href="...">文字</a>` 链接；
- **图文消息 news** ✅ —— **带图**：大图 + 标题 + 描述 + 点击跳转，**微信里最接近卡片的形态**，需要微信也能收到时首选它；
- **文本卡片 textcard** ✅ —— 带标题与跳转按钮，需要同时填写「卡片标题」和「卡片跳转链接」；
- **markdown** ❌ —— 企业微信 markdown 子集（标题、加粗、引用、行内代码、`<font color="info|warning|comment">` 彩色字、链接），排版好看但**微信收不到**；
- **卡片通知 template_card** ❌ —— **带图卡片**：大图 + 标题 + 键值列表，样式最丰富但**微信收不到**，参数见 [五、卡片通知](#五卡片通知带图)。

> 微信可收性是企业微信的官方限制，详见 [七、在微信中接收消息](#七在微信中接收消息)。

## 二、准备：企业微信后台要做什么

1. 登录 [企业微信管理后台](https://work.weixin.qq.com/)。
2. **我的企业 → 企业信息**：复制「企业 ID」（`corpid`，通常以 `ww` 开头）。
3. **应用管理 → 自建应用 → 创建应用**（或用已有应用），进入应用详情：
   - 复制 **AgentId**（纯数字）；
   - 复制 **Secret**（点「查看」，只显示一次，请及时保存）；
   - 把需要接收消息的成员 / 部门加入 **可见范围**。
4. **企业可信 IP**（关键）：
   - 2022 年 6 月 28 日之后**新创建**的自建应用，必须把服务器出口 IP 加入应用详情里的「企业可信IP」，否则调用接口会返回 `60020`；
   - 如果服务器出口 IP 不固定，可在应用详情填写一个**转发代理地址**，然后在插件的「代理地址」里填它 —— 请求会发往「代理地址 + `/cgi-bin/...`」，由代理的固定 IP 调用企业微信接口。

> 拿不到出口 IP 时有个小技巧：先随便发一次（或点「检查配置」），报错信息里的 `60020` 会带上实际调用的 IP，插件会把它直接显示在结果页。

## 三、配置字段说明

界面分四个页签（发送消息 / 卡片通知 / 应用配置 / 回调与高级），右上角两个按钮（「发送测试消息」「查看调用方法」）。

### 应用配置

| 字段 | 说明 |
| --- | --- |
| 通知渠道名称 | 只用于界面显示与测试消息前缀，随意填写（例如 `WX`） |
| 企业 ID | 必填，企业微信的 `corpid` |
| 应用 AgentId | 必填，纯数字 |
| 应用 Secret | 必填，自建应用的 Secret |
| 代理地址 | 默认 `https://qyapi.weixin.qq.com`；使用转发代理时改写为代理地址 |
| 网络代理 | 默认**「不使用代理（直连）」**。转发代理地址通常是「只允许特定地区访问」的服务，若插件跟随容器的 `HTTP_PROXY` / `HTTPS_PROXY`，请求会被送去代理而直接连不通（表现为 `SSLError ... UNEXPECTED_EOF_WHILE_READING`）。只有容器必须经代理才能出网时，才改成「跟随容器环境变量代理」 |

### 发送消息

| 字段 | 说明 |
| --- | --- |
| 执行功能 | 界面上只有 `test` / `config` / `history` / `docs`；`send` 仅供其它插件调用 |
| 消息类型 | `text` / `news` / `textcard` / `markdown` / `template_card` |
| 接收成员 | UserID，多个用 `\|` 分隔，最多 1000 个；`@all` 表示全体可见成员 |
| 接收部门 / 标签 | 部门 ID / 标签 ID，多个用 `\|` 分隔；`touser` 为 `@all` 时被忽略 |
| 保密消息 | 对应接口 `safe=1`：不可分享且带水印 |
| 卡片标题 / 跳转链接 | `textcard` 必填；`news` 会使用（`url` 为空时回退官方站点） |
| 消息内容 | 正文；`test` 功能会忽略它 |

### 回调与高级

| 字段 | 说明 |
| --- | --- |
| 回调 Token | 自建应用「接收消息」配置里的 Token |
| EncodingAESKey | 同上，43 位 Base64 |
| 管理员白名单 | 成员 ID 列表；当「成员 / 部门 / 标签」都为空时，作为兜底收件人 |
| 超长消息自动分段 | 超过 2048 字节时按行边界切成多条依次发送并标注段落序号 |
| 历史记录保留天数 | 本地历史保留时长 |
| TgtoDrive 地址 / OpenAPI 令牌 | 可选；企业 ID 或 Secret 留空时，插件会尝试从 TgtoDrive 已保存的项目设置里读取微信渠道配置作为兜底 |

> **关于 Token / EncodingAESKey**：它们用于企业微信**推送消息给你**时的签名与解密。插件是一次性执行、无常驻进程，收不到回调，因此这两项仅做**配置留档与格式校验**（不对格式会在日志里提示），**不影响消息发送**。

### 收件人优先级

```
接收成员 / 部门 / 标签  →  管理员白名单  →  @all（全体可见成员）
```

## 四、发送测试消息

界面上的内容输入框已经移除，测试内容**内置在插件里**，点右上角 **「发送测试消息」** 即可：

1. 先发一条**文本消息**（内置文案，含当前时间、渠道与接口地址）；
2. **间隔 3 秒**；
3. 再发一条**卡片消息** —— 按「消息类型」里选中的卡片类发送：

| 「消息类型」 | 第二条实际发送 | 微信能否收到 |
| --- | --- | --- |
| 文本 `text` | 模板卡片（内置 4 条键值） | ❌ |
| 图文消息 `news` | 图文消息（大图 + 标题 + 「状态：测试成功」等多行描述） | ✅ |
| 文本卡片 `textcard` | 文本卡片 | ✅ |
| markdown / 卡片通知 `template_card` | 模板卡片（内置 4 条键值） | ❌ |

> **想让微信也收到，就先把「消息类型」选成「图文消息 news」** 再点按钮 —— 这样一次点击就能同时验证企业微信与微信两条链路。

想让测试内容按自己的场景走时，用其它插件调用并传 `content` / `card_content` 覆盖内置内容（见 [CALLING.md](CALLING.md)）。

超长正文（> 2048 字节）会自动分段，每段末尾标注 `（第 x/y 段）`；关闭「超长消息自动分段」时只发第一段并在日志中提示。

## 五、卡片通知（带图）

把「消息类型」选为 **卡片通知 template_card**，然后到「卡片通知」页签填写卡片参数。
卡片是单条消息，不做分段；`text_notice` 的效果是「大图 + 标题 + 键值列表」。

| 字段 | 说明 |
| --- | --- |
| 卡片类型 | `text_notice`（默认，大图+键值列表）/ `news_notice`（图文展示型） |
| 卡片图片 | 卡片主图。可填 **http(s) 链接**、**内网地址**（如 `http://192.168.x.x/...`）或**容器内本地图片路径** —— 后两种企业微信都取不到，插件会自动下载并调 `media/uploadimg` 换取企业微信可用的图片 URL。建议 1068×455、JPG/PNG、≤2 MB |
| 卡片来源名称 | 左上角小字，例如 `站点 1PTBA 消息`（≤20 字） |
| 来源图标链接 | 来源名称左边的小图标（可留空） |
| 卡片副标题 | 标题下方一行说明（≤30 字） |
| 卡片内容（`card_content`） | **界面无此输入框**。「发送测试消息」用内置的 4 条键值；其它插件调用时可传入企业微信原生 JSON（原样发送）或「键=值」列表 |
| 卡片图片比例 | 1.3–2.25，默认 2.25（宽图） |
| 卡片标题 / 卡片跳转链接 | 复用「发送消息」页签的「卡片标题」与「卡片跳转链接」 |

键值列表的写法（`=`、`:`、`：`、`|` 都能分隔）：

```text
时间=2026-10-13 18:04:48
季集=S01E15 第 15 集
分类=日番
评分=8.5/10
```

几条硬限制（企业微信侧，插件会主动截断并在日志中说明，避免静默丢字）：

- 键值列表 **最多 6 条**，超出部分丢弃；
- 键 ≤5 字、值 ≤30 字 —— 这也是为什么长剧情会被截断；
- 模板卡片必须有 `card_action`，即「卡片跳转链接」；留空时会回退到企业微信官网并在日志中提示；
- `news_notice` 必须有卡片图片，没有图片时会自动改用 `text_notice`；
- 卡片不支持「保密消息」。

## 六、被其他插件调用

本插件可以作为**企业微信通知出口**被其他插件调用，无需重复实现企业微信接口：

```python
import os, requests

base = os.environ.get("TGTO_OPENAPI_BASE_URL", "http://127.0.0.1:12366").rstrip("/")
token = os.environ["TGTO_OPENAPI_TOKEN"]

requests.post(
    base + "/api/toolbox/plugins/wecom-notify/run",
    headers={"Authorization": "Bearer " + token},
    json={"params": {
        "func": "send",
        "msgtype": "template_card",
        "touser": "@all",
        "title": "新入库剧集：示例标题",
        "card_source": "站点 1PTBA 消息",
        "card_image": "https://example.com/cover.jpg",
        "card_content": "时间=2026-10-13 18:04\n分类=日番",
        "url": "https://example.com/detail",
    }},
    timeout=(5, 30),
)
```

- `params` 里只需放本次变化的字段，其余沿用用户已保存的配置（凭据不必传、也拿不到）；
- **不要传 `save_settings: true`**，否则会把调用参数写进用户的插件设置；
- 完整参数表、返回值结构、结果轮询、错误处理与更多场景：
  **[CALLING.md](CALLING.md)**（插件界面点「查看调用方法」也能直接拿到链接）。

## 七、在微信中接收消息

**企业微信自建应用下发的消息，默认只出现在「企业微信」客户端，不会进个人微信。**
要在微信里收到，需要走官方的「**微信插件**」（原企业号）—— 它是企业成员在**微信客户端**中接收企业通知的载体。

### 先说最重要的一条：哪些消息类型微信收不到

| 消息类型 | 企业微信客户端 | 微信（关注微信插件后） | 依据 |
| --- | --- | --- | --- |
| 文本 `text` | ✅ | ✅ 完整内容 | — |
| **图文消息 `news`** | ✅ | ✅ **带图 + 标题 + 描述 + 跳转** | 微信里最接近卡片的形态 |
| 文本卡片 `textcard` | ✅ | ✅ 带标题与跳转按钮 | 官方技术支持确认 |
| `markdown` | ✅ | ❌ **收不到** | 文档：「微工作台（原企业号）不支持展示 markdown 消息」 |
| **卡片通知 `template_card`** | ✅ | ❌ **收不到** | 官方技术支持：「微信插件不支持接收模板卡片消息」 |
| 小程序应用消息 | ✅ | ❌ 收不到 | 官方技术支持同答 |
| 图片 / 语音 / 视频 / 文件 | ✅ | ⚠️ 只提示「在企业微信中查看」 | — |

**这意味着：只要用的是模板卡片或 markdown，企业微信里能看到、微信里一定看不到 —— 和收件人权限、可见范围都无关。**

### 想让卡片在微信也能收到：改用「图文消息 news」

「图文消息 `news`」有 **大图 + 标题 + 描述 + 点击跳转**，是微信里最接近卡片的形态，而且**微信插件可以完整接收**。

切换成本极低 —— **只把「消息类型」从「卡片通知」改成「图文消息 news」，内容不用动**：
插件会**自动把现有的模板卡片 JSON 转换成图文消息**（提取 `main_title` / `emphasis_content` / `sub_title_text` / `horizontal_content_list` / `card_action` / `card_image`），并在日志中说明。

> ⚠️ 上一版 README 曾把 `markdown` 标为「微信可收」，这是**错的** —— 企业微信文档明确「微工作台（原企业号）不支持展示 markdown 消息」。已更正。

### 开启步骤

1. **管理员**：登录企业微信管理后台 →「我的企业 → 微信插件」，获取「邀请关注微信插件」的二维码（有效期 7 天）。
2. **成员**：用**微信**扫描该二维码，关注本企业的微信插件。
3. 关注后，在 微信 → 通讯录 → 该企业 → 右上角「+」→ 设置 里确认「**接收应用消息**」开关已打开。

### 仍收不到时逐项检查（官方给出的前提条件）

| 检查点 | 位置 |
| --- | --- |
| 消息开关是否开启 | 微信插件 → 右上角 → 设置 → 接收应用消息 |
| **「在微工作台中始终进入主页」是否被勾选** | 管理后台 → 该应用 → 勾选后应用在微信端**只能收到文本消息**（其他类型会被转成「到企业微信查看」的提示），**这一项最容易被忽略** |
| 应用是否被停用 | 微信插件 → 进入应用 → 右上角 → 停用 |
| 后台是否强制使用企业微信 | 管理后台 → 微信插件 →「成员使用微信插件时需要使用企业微信客户端」**不可勾选** |
| 手机端是否只收企业微信消息 | 企业微信 App → 左上角「≡」→ 设置 → 新消息通知 →「仅在企业微信中接收消息」**不可勾选**（该项需关注微信插件后才会出现） |

另外：全员群人数超过 2000 人时消息不同步到微信插件；若以上都正常仍收不到，可取消关注微信插件后重新关注，并把微信更新到最新版本。

> 参考：企业微信帮助中心「[什么是微信插件](https://open.work.weixin.qq.com/help2/pc/14797)」与「[How to receive WeChat Workplace messages](https://open.work.weixin.qq.com/help2/pc/18121)」。

### 插件侧能帮你确认什么

发送时插件会自动做**投递校验**，并把结果写进结果页与运行日志：

- `接收人：成员 xxx｜部门 -｜标签 -` —— 实际发给了谁（没填收件人时会回退成 `@all`，日志里会写明）；
- `投递校验：收件人均在可见范围内（可见成员共 N 人）`；
- 收件人**不在应用可见范围**、或可见范围为空时给出告警 —— 这种情况企业微信**仍会返回 `errcode=0` 与 msgid，但消息不会投递**，只看返回值会误判成功。

> 注意：可见范围校验依赖 `GET /cgi-bin/user/list`。若「代理地址」是只转发 `gettoken` 与
> `message/send` 的自建中转（此时该接口返回 404），校验会自动跳过 —— 这时以企业微信返回值里的
> `invaliduser` 为准：插件会把里面列出的收件人当作「无效收件人」在日志与结果页点名告警。

## 八、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `60020` IP 不在可信名单 | 把报错里给出的出口 IP 加入应用「企业可信IP」（约 1 分钟生效），或在「代理地址」填转发代理 |
| `SSLError` / `UNEXPECTED_EOF_WHILE_READING`，或 `Max retries exceeded` | 「代理地址」是只允许特定地区访问的转发服务，而请求走了容器代理（`HTTP_PROXY` / `HTTPS_PROXY`） | 把「网络代理」保持为**「不使用代理（直连）」**。网络类失败时结果页会自动给出 **DNS → TCP → TLS** 三层自检结论，直接指出卡在哪一层 |
| 接口返回成功（有 msgid），**企业微信客户端能收到**，但**个人微信收不到** | ① 用的是「卡片通知」（`template_card`）或 `markdown` —— **这两类微信插件根本收不到**；② 用的是微信可收的类型，则是没关注微信插件、或勾选了「在微工作台中始终进入主页」、或消息开关没开 | ① 把「消息类型」改成 **图文消息 news**（现有的卡片 JSON 会**自动转换**成图文）；② 按[七、在微信中接收消息](#七在微信中接收消息)逐项检查 |
| 接口返回成功（有 msgid）但**企业微信客户端也收不到** | 收件人不在应用的「可见范围」内 | 企业微信此时仍返回 `errcode=0`，但会把该收件人列进返回值的 `invaliduser` 字段。插件会在日志与结果页点名告警；请到管理后台该应用的「可见范围」里加入他们 |
| `40001` / `40013` | Secret 或企业 ID 不正确（Secret 重置过需重新复制） |
| `42001` / `40014` | access_token 过期；插件会自动清缓存重取一次 |
| `60011` / `82001` | 接收者不在应用可见范围内，或 UserID / 部门 ID 写错 |
| `45009` | 触发频率限制：每应用每天有人次上限，单成员每分钟不超过 30 条 |
| 收到消息但姓名显示为空 | 部分应用类型下成员姓名不返回，属企业微信侧策略，不影响发送 |

## 十二、安全与隐私

- Secret、EncodingAESKey、OpenAPI 令牌**不会**出现在运行日志、返回值与结果页中，仅显示「已填写（长度 N）」；企业 ID 与成员 ID 做掩码处理。
- 插件设置以**明文 JSON** 保存在服务器的插件目录，管理员可读取；更在意安全时请把「应用 Secret」留空，改用环境变量 `TGTO_WECOM_CORP_SECRET`。
- 唯一的写操作是插件数据目录下的 `token.json`（access_token 缓存）与 `history.json`（发送历史），**不写插件源码目录**。
- 不读取与需求无关的任何配置或凭据。

## 十三、实现与协议说明

- `access_token` 按「代理地址 + 企业 ID」缓存，提前 300 秒视为过期，避免频繁调用 `gettoken` 被限流。
- 命中 token 失效类错误（`40014` / `41001` / `42001`）时自动清缓存重取并重试**一次**。
- 分段时按行边界切分并逐字符累计字节数，不会切断 UTF-8 字符。
- 插件为同步 `run(params, context)`，不含异步、不含常驻线程；所有网络请求都在 `run` 内发起。
- 仅写入 `context["data_dir"]`，不触碰 `plugin_dir`。
