# 企业微信通知 · TgtoDrive 插件

为 **TgtoDrive** 补上企业微信（WeCom）通知能力：填写企业自建应用的凭据后，即可把消息推送给成员、部门、标签或全体可见成员。它同时是**其他插件的企业微信通知出口** —— 别的插件通过 OpenAPI 调用它即可发微信通知，不必重复实现企业微信接口。

按企业微信官方接口实现：`GET /cgi-bin/gettoken` 与 `POST /cgi-bin/message/send`
（参考 <https://developer.work.weixin.qq.com/document>）。

- **插件 id**：`wecom-notify`
- **版本**：`1.0.0`
- **作者**：`a2695154202`
- **入口**：`plugin.py`
- **超时**：120 秒
- **依赖**：仅使用 Python 标准库 + 容器已安装的 `requests`（不可用时自动回退 `urllib`）。**不安装任何依赖。**
- **许可证**：GPL-3.0（与本仓库一致）

> ⚠️ **插件不含任何内置凭据。** 企业 ID、AgentId、Secret、Token、EncodingAESKey、白名单全部由你填写，代码里不存在示例值。

## 一、它能做什么

### 消息类型：只有两种

| 类型 | 形态 | 微信插件能否收到 |
| --- | --- | --- |
| **文本消息 `text`** | 纯文本，支持换行与 `<a href="...">文字</a>` 链接；正文上限 2048 字节（约 680 汉字） | ✅ 完整内容 |
| **图文消息 `news`** | 大图 + 标题 + 描述 + 点击跳转；标题 ≤128 字节、描述 ≤512 字节 | ✅ 带图完整显示 |

**为什么只有这两种**：企业微信官方限制下，微信插件（原企业号 / 微工作台）**收不到** markdown 与模板卡片 `template_card`；文本卡片 `textcard` 的功能已被 `news` 覆盖。既然本插件的定位是「让 TgtoDrive 能把消息发到微信」，就只保留微信确实能收到的两种 —— 这样**不存在「发出去了但微信收不到」的配置陷阱**。

> 兼容：如果你的内容本来就是**模板卡片 JSON**，把它放进 `card_content` 并选 `news`，插件会**自动转换成图文消息**（提取标题 / 描述 / 键值 / 链接 / 图片），不必重写内容。

### 界面功能（`func`）

界面顶部两个按钮：「发送测试消息」「查看调用方法」；「执行功能」下拉框共 5 项：

| 功能（`func`） | 说明 |
| --- | --- |
| **发送消息（`send`）** | 正式发送，需要传入正文。主要**供其他插件调用**（药丸签到等走这条路径），也可以在本界面选它、填好「消息正文」后运行 |
| **发送测试消息（`test`）** | 内容**已内置**：固定发一条文本 + 一条图文消息（**间隔 3 秒**，共两条），一次点击验证「配置 + 网络 + 收件人 + 微信可收性」。界面右上角有独立按钮 |
| 检查配置（`config`） | 逐项校验必填与格式，并真实获取一次 `access_token`，给出剩余有效期 |
| 查看发送历史（`history`） | 本地记录每次发送的时间、类型、收件人、结果与 msgid |
| **查看调用方法（`docs`）** | 输出「被其他插件调用」的参数表、示例与在线文档链接，界面右上角有独立按钮 |

> `send` **必须留在下拉框里**：TgtoDrive 会校验 `select` 的取值是否在清单的 `options` 内，
> 若把 `send` 从选项里去掉，其他插件调用 `func=send` 时请求会被直接拒绝（HTTP 400）。

## 二、准备：企业微信后台要做什么

1. 登录 [企业微信管理后台](https://work.weixin.qq.com/)。
2. **我的企业 → 企业信息**：复制「企业 ID」（`corpid`，通常以 `ww` 开头）。
3. **应用管理 → 自建应用 → 创建应用**（或用已有应用），进入应用详情：
   - 复制 **AgentId**（纯数字）；
   - 复制 **Secret**（点「查看」，只显示一次，请及时保存）；
   - 把需要接收消息的成员 / 部门加入 **可见范围**。
4. **企业可信 IP**（关键）：
   - 2022 年 6 月 28 日之后**新创建**的自建应用，必须把服务器出口 IP 加入应用详情里的「企业可信IP」，否则调用接口会返回 `60020`；
   - 如果服务器出口 IP 不固定，可在应用详情填写一个**转发代理地址**，然后在插件的「代理地址」里填它 —— 请求会发往「代理地址 + `/cgi-bin/...`」，由代理的固定 IP 调用企业微信接口。

> 拿不到出口 IP 时有个小技巧：先随便发一次（或点「检查配置」），报错信息里的 `60020` 会带上实际调用的 IP，插件会把它直接显示在结果页。

## 三、配置字段说明

界面**只有一个「应用配置」页**，所有字段都在里面，按三个分组排列；右上角两个按钮（「发送测试消息」「查看调用方法」）。

### ① 应用凭据（必填）

| 字段 | 说明 |
| --- | --- |
| 企业 ID | 必填，企业微信的 `corpid` |
| 应用 AgentId | 必填，纯数字 |
| 应用 Secret | 必填，自建应用的 Secret |
| 代理地址 | 默认 `https://qyapi.weixin.qq.com`；使用转发代理时改写为代理地址 |
| 网络代理 | 默认**「不使用代理（直连）」**。转发代理地址通常是「只允许特定地区访问」的服务，若插件跟随容器的 `HTTP_PROXY` / `HTTPS_PROXY`，请求会被送去代理而直接连不通（表现为 `SSLError ... UNEXPECTED_EOF_WHILE_READING`）。只有容器必须经代理才能出网时，才改成「跟随容器环境变量代理」 |
| 通知渠道名称 | 只用于界面显示与图文标题前缀，随意填写（例如 `WX`） |

### ② 发送参数

| 字段 | 说明 |
| --- | --- |
| 执行功能 `func` | 见上表；`send` 供其他插件调用，也可在本界面直接发送 |
| 消息类型 `msgtype` | 只有 `text` / `news` 两种 |
| 接收成员 `touser` | UserID，多个用 `\|` 分隔，最多 1000 个；`@all` 表示全体可见成员 |
| 接收部门 / 标签 | 部门 ID / 标签 ID，多个用 `\|` 分隔；`touser` 为 `@all` 时被忽略 |
| 保密消息 `safe` | 仅 `text` 支持：`safe=1` 时不可分享且带水印。`news` 不支持，勾选后会被忽略并在日志说明 |
| 图文消息标题 `title` | `news` 使用；留空时取「渠道名称 + 通知」 |
| 点击跳转链接 `url` | `news` 使用；留空时回退官方站点 |
| 图片 `card_image` | `news` 的主图。可填 **http(s) 链接**、**内网地址**（如 `http://192.168.x.x/...`）或**容器内本地图片路径** —— 后两种企业微信都取不到，插件会自动下载并调 `media/uploadimg` 换取企业微信可用的图片 URL。建议 1068×455、JPG/PNG、≤2 MB |
| 消息正文 `content` | `text` 的正文，也是 `news` 的描述。点「发送测试消息」时：填了就用你填的，留空用内置示例 |
| 图文消息描述备用 `card_content` | 「消息正文」为空时作为 `news` 的描述。支持每行一条「键=值」，也支持直接粘贴企业微信原生 JSON（`news` / `articles` 原样发送；`card_type` 自动转图文） |
| 标准化发送内容 `envelope` | **供其他插件调用（推荐）**：JSON 字符串，字段表与覆盖优先级见 [CALLING.md](CALLING.md) 第三节。给了它就以它为准、覆盖上面的内容类字段；本界面手动发送时留空即可 |

### ③ 回调与高级

| 字段 | 说明 |
| --- | --- |
| 回调 Token | 自建应用「接收消息」配置里的 Token |
| EncodingAESKey | 同上，43 位 Base64 |
| 管理员白名单 | 成员 ID 列表；当「成员 / 部门 / 标签」都为空时，作为兜底收件人 |
| 超长消息自动分段 | 超过 2048 字节时按行边界切成多条依次发送并标注段落序号 |
| 历史记录保留天数 | 本地历史保留时长 |
| TgtoDrive 地址 / OpenAPI 令牌 | 可选；企业 ID 或 Secret 留空时，插件会尝试从 TgtoDrive 已保存的项目设置里读取微信渠道配置作为兜底 |

> **关于 Token / EncodingAESKey**：它们用于企业微信**推送消息给你**时的签名与解密。插件是一次性执行、无常驻进程，收不到回调，因此这两项仅做**配置留档与格式校验**（不对格式会在日志里提示），**不影响消息发送**。

### 收件人优先级

```
接收成员 / 部门 / 标签  →  管理员白名单  →  @all（全体可见成员）
```

## 四、发送测试消息

点右上角 **「发送测试消息」** 即可，测试内容**内置在插件里**，无需先填写：

| 顺序 | 内容 | 消息类型 |
| --- | --- | --- |
| 1 | 内置测试文本（含当前时间、渠道、接口地址） | 文本消息 `text` |
| 2 | 间隔 **3 秒** 后 | 图文消息 `news`（大图 + 标题 + 多行描述） |

两条都是微信插件能收到的类型，所以**一次点击就能同时验证企业微信与微信两条链路**。

想让测试内容按自己的场景走时，用其他插件调用并传 `content` / `card_content` 覆盖内置内容（见 [CALLING.md](CALLING.md)）。

超长正文（> 2048 字节）会自动分段，每段末尾标注 `（第 x/y 段）`；关闭「超长消息自动分段」时只发第一段并在日志中提示。

## 五、图文消息（带图）

「图文消息 `news`」是微信里最接近卡片的形态：**大图 + 标题 + 描述 + 点击跳转**，且微信插件可以完整接收。

| 字段 | 说明 |
| --- | --- |
| 图文消息标题 | 标题（≤128 字节，插件会按 60 字符保守截断并在日志说明） |
| 点击跳转链接 | 点击后的跳转地址；留空回退官方站点 |
| 图片 | 主图，支持 http(s) / 内网地址 / 容器内本地路径 |
| 消息正文 / 图文消息描述备用 | 描述内容；描述超过 512 字节会被截断并在日志说明 |

描述用「键=值」列表的写法（`=`、`:`、`：`、`|` 都能分隔）：

```text
时间=2026-10-13 18:04:48
季集=S01E15 第 15 集
分类=日番
评分=8.5/10
```

也可以直接把企业微信原生 JSON 粘进「图文消息描述备用」：含 `news` / `articles` 时原样发送；
含 `card_type`（模板卡片）时会**自动转换成图文消息**，无需重写内容。

## 六、被其他插件调用

本插件既是**能独立使用的通知插件**，也是**通用的发送模块** —— 其他插件不必重复实现企业微信接口，
只要准备一份**标准化发送内容**（`envelope`）交给它即可。

### 推荐用法：只传「标准化发送内容」

```python
import os, json, requests

base = os.environ.get("TGTO_OPENAPI_BASE_URL", "http://127.0.0.1:12366").rstrip("/")
token = os.environ["TGTO_OPENAPI_TOKEN"]

envelope = {
    "version": 1,
    "msgtype": "news",                       # text / news
    # "touser": "zhangsan|lisi",             # 省略 = 沿用本插件已保存的收件人（推荐）
    "title": "新入库剧集：示例标题",
    "content": "时间=2026-10-13 18:04\n分类=日番",
    "url": "https://example.com/detail",
    "image": "https://example.com/cover.jpg",
    "source": "我的插件",                     # 只写进日志，便于追溯
}

requests.post(
    base + "/api/toolbox/plugins/wecom-notify/run",
    headers={"Authorization": "Bearer " + token},
    json={"params": {"func": "send", "envelope": json.dumps(envelope, ensure_ascii=False)}},
    timeout=(5, 30),
)
```

**调用参数只有 `func` 与 `envelope` 两个键**，发送逻辑（凭据、企业微信请求体、分段、投递校验）
全部由本插件负责。字段表、覆盖优先级与配置加载时机见
[`CALLING.md` §三](CALLING.md)。

### 被调用时会把收到的参数写进运行日志

无论谁调用本插件（界面、定时计划、其他插件），它都会在**开头的运行日志**里打印收到的参数：

```text
[INFO] 收到调用参数（共 2 个键，敏感项已脱敏）：func=send | envelope={"version": 1, "msgtype": "text", "content": "…"}
[INFO] 本次将发送：消息类型=文本消息｜收件人=zhangsan｜标题=（无）｜正文 26 字｜内容来自调用方「药丸论坛签到」
```

两行配合看，就能分清「对方没传」与「本插件没接住」：

| 日志 | 作用 |
| --- | --- |
| `收到调用参数` | **对方到底传了什么**（键与值；`envelope` 内容原样展开） |
| `本次将发送` | **最终生效的值**（消息类型 / 收件人 / 标题 / 正文字数 / 内容来源） |

安全约定：**凭据类字段只显示「已填写（长度 N）」**，绝不会把明文写进日志。
判定依据是键名归一化后含 `secret` / `token` / `password` / `aeskey` / `credential` / `apikey`
等片段 —— 所以**不要给非凭据字段起这些名字**。单行超过 2000 字会截断并标注。

### 也可以逐个字段传（兼容用法）

`msgtype` / `touser` / `content` / `title` / `url` / `card_image` 仍然可用：

```python
json={"params": {
    "func": "send", "msgtype": "text", "touser": "@all", "content": "任务已完成",
}}
```

**两条硬约束**（调用失败几乎都是踩了这两条）：

1. `params` 的每个键都必须是本插件清单里**已声明**的输入，否则请求被判「未知参数」拒绝（HTTP 400）；
2. `select` 字段的取值必须在该字段的 `options` 内 —— 例如 `func` 只能是
   `send` / `test` / `config` / `history` / `docs`，`msgtype` 只能是 `text` / `news`。
   （`envelope` 的内容由本插件自己校验：未知字段会**报错并列出允许的字段**，不会静默忽略。）

**凭据与收件人由本插件自己补齐**（调用方不必传）：

TgtoDrive 的运行接口**不会**把用户在本插件表单里保存的设置合并进来（它只按清单填默认值，见下方坑），
所以本插件执行前会先从**自己已保存的设置**里补齐调用方没传的字段：

```text
优先级：调用方显式传的值  >  本插件已保存的设置（settings.json）  >  内置默认值
```

- 调用方**只需传内容**（`func` / `msgtype` / `content`），凭据（企业 ID / AgentId / Secret）、
  `api_base`、`proxy_mode`、`touser` 等都从用户已保存的设置里取；
- **`func` 不参与补齐** —— 表单里通常存的是 `test`，沿用它会让外部调用变成「发一条测试消息」，
  所以 `func` 始终以调用方传入的为准（不传则默认 `send`）；
- 运行日志会打印 `已从本插件已保存的设置（settings.json）补齐 N 项未传参数：…`；
- 若用户从未保存过凭据、调用方也没传，会明确报 `缺少必填配置：企业 ID、应用 AgentId、应用 Secret`，
  **不会静默发出空凭据**。

> ⚠️ **坑：平台会把清单默认值填齐，别被「传了值」的假象骗了**
>
> TgtoDrive 并不是只把调用方传的键交给插件 —— 它会按插件清单把所有 `inputs` 都用**默认值**填齐
> （线上实测：调用方只传 `func` + `envelope` 两个键，本插件却收到 **25 个键**）。
> 于是「值为空」不再等于「调用方没传」：
>
> - `corp_id` / `corp_secret` 这类**默认值为空**的字段，上面的补齐逻辑能正确顶上；
> - `api_base`（默认官方地址）、`touser`（默认 `@all`）、`card_image`（默认品牌图）这类
>   **默认值非空**的字段，会被默认值永久顶掉 —— 表现为「表单里配了转发代理地址，
>   被调用时却从服务器真实 IP 直连官方接口、报 `60020`」。
>
> 因此本插件把「**值等于该输入在清单里的默认值**」同样判定为调用方没有显式传，
> 让已保存的设置顶回它（`func` 与 `msgtype` 例外：调用方对这两个字段有明确意图）。
> 调用方若确实想显式指定 `touser` / `api_base`，传一个**与默认值不同**的值即可。
> 详见 [CALLING.md](CALLING.md) 同名小节。

其他要点：

- `params` 里只需放本次变化的字段，其余沿用用户已保存的配置；
- **不要传 `save_settings: true`**，否则会把调用参数写进用户的插件设置；
- 完整参数表、返回值结构、结果轮询、错误处理与更多场景：
  **[CALLING.md](CALLING.md)**（插件界面点「查看调用方法」也能直接拿到链接）。

## 七、在微信中接收消息

**企业微信自建应用下发的消息，默认只出现在「企业微信」客户端，不会进个人微信。**
要在微信里收到，需要走官方的「**微信插件**」（原企业号）—— 它是企业成员在**微信客户端**中接收企业通知的载体。

### 消息类型与微信可收性

| 消息类型 | 企业微信客户端 | 微信（关注微信插件后） | 依据 |
| --- | --- | --- | --- |
| 文本 `text` | ✅ | ✅ 完整内容 | — |
| **图文消息 `news`** | ✅ | ✅ **带图 + 标题 + 描述 + 跳转** | 微信里最接近卡片的形态 |
| ~~`markdown`~~ | ✅ | ❌ 收不到 | 文档：「微工作台（原企业号）不支持展示 markdown 消息」 |
| ~~`textcard`~~ | ✅ | ✅（已移除该类型） | 功能被 `news` 覆盖 |
| ~~`template_card`~~ | ✅ | ❌ 收不到 | 官方技术支持：「微信插件不支持接收模板卡片消息」 |
| 小程序应用消息 | ✅ | ❌ 收不到 | 官方技术支持同答 |
| 图片 / 语音 / 视频 / 文件 | ✅ | ⚠️ 只提示「在企业微信中查看」 | — |

> 划掉的三种类型**本插件已不再提供**，所以你不会再用到「企业微信能看到、微信看不到」的类型 —— 这正是当初收窄到两种的原因。

### 开启步骤

1. **管理员**：登录企业微信管理后台 →「我的企业 → 微信插件」，获取「邀请关注微信插件」的二维码（有效期 7 天）。
2. **成员**：用**微信**扫描该二维码，关注本企业的微信插件。
3. 关注后，在 微信 → 通讯录 → 该企业 → 右上角「+」→ 设置 里确认「**接收应用消息**」开关已打开。

### 仍收不到时逐项检查（官方给出的前提条件）

| 检查点 | 位置 |
| --- | --- |
| 消息开关是否开启 | 微信插件 → 右上角 → 设置 → 接收应用消息 |
| **「在微工作台中始终进入主页」是否被勾选** | 管理后台 → 该应用 → 勾选后应用在微信端**只能收到文本消息**（其他类型会被转成「到企业微信查看」的提示），**这一项最容易被忽略** |
| 应用是否被停用 | 微信插件 → 进入应用 → 右上角 → 停用 |
| 后台是否强制使用企业微信 | 管理后台 → 微信插件 →「成员使用微信插件时需要使用企业微信客户端」**不可勾选** |
| 手机端是否只收企业微信消息 | 企业微信 App → 左上角「≡」→ 设置 → 新消息通知 →「仅在企业微信中接收消息」**不可勾选**（该项需关注微信插件后才会出现） |

另外：全员群人数超过 2000 人时消息不同步到微信插件；若以上都正常仍收不到，可取消关注微信插件后重新关注，并把微信更新到最新版本。

> 参考：企业微信帮助中心「[什么是微信插件](https://open.work.weixin.qq.com/help2/pc/14797)」与「[How to receive WeChat Workplace messages](https://open.work.weixin.qq.com/help2/pc/18121)」。

### 插件侧能帮你确认什么

发送时插件会自动做**投递校验**，并把结果写进结果页与运行日志：

- `接收人：成员 xxx｜部门 -｜标签 -` —— 实际发给了谁（没填收件人时会回退成 `@all`，日志里会写明）；
- `投递校验：收件人均在可见范围内（可见成员共 N 人）`；
- 收件人**不在应用可见范围**、或可见范围为空时给出告警 —— 这种情况企业微信**仍会返回 `errcode=0` 与 msgid，但消息不会投递**，只看返回值会误判成功。

> 注意：可见范围校验依赖 `GET /cgi-bin/user/list`。若「代理地址」是只转发 `gettoken` 与
> `message/send` 的自建中转（此时该接口返回 404），校验会自动跳过 —— 这时以企业微信返回值里的
> `invaliduser` 为准：插件会把里面列出的收件人当作「无效收件人」在日志与结果页点名告警。

## 八、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `60020` IP 不在可信名单 | 把报错里给出的出口 IP 加入应用「企业可信IP」（约 1 分钟生效），或在「代理地址」填转发代理 |
| `SSLError` / `UNEXPECTED_EOF_WHILE_READING`，或 `Max retries exceeded` | 「代理地址」是只允许特定地区访问的转发服务，而请求走了容器代理（`HTTP_PROXY` / `HTTPS_PROXY`） | 把「网络代理」保持为**「不使用代理（直连）」**。网络类失败时结果页会自动给出 **DNS → TCP → TLS** 三层自检结论，直接指出卡在哪一层 |
| 接口返回成功（有 msgid），**个人微信收不到** | 没关注微信插件、或勾选了「在微工作台中始终进入主页」、或消息开关没开 | 按[七、在微信中接收消息](#七在微信中接收消息)逐项检查。（本插件只发 `text` / `news`，两者微信都收得到，不必再怀疑消息类型） |
| 接口返回成功（有 msgid）但**企业微信客户端也收不到** | 收件人不在应用的「可见范围」内 | 企业微信此时仍返回 `errcode=0`，但会把该收件人列进返回值的 `invaliduser` 字段。插件会在日志与结果页点名告警；请到管理后台该应用的「可见范围」里加入他们 |
| 调用本插件返回 **HTTP 400**（其他插件接入时） | 传了未声明的参数，或 `select` 取值不在选项内（如用了已移除的 `markdown` / `template_card`） | 对照 [CALLING.md](CALLING.md) 的参数表逐项核对；`func` 用 `send`，`msgtype` 用 `text` 或 `news` |
| `40001` / `40013` | Secret 或企业 ID 不正确（Secret 重置过需重新复制） |
| `42001` / `40014` | access_token 过期；插件会自动清缓存重取一次 |
| `60011` / `82001` | 接收者不在应用可见范围内，或 UserID / 部门 ID 写错 |
| `45009` | 触发频率限制：每应用每天有人次上限，单成员每分钟不超过 30 条 |
| 收到消息但姓名显示为空 | 部分应用类型下成员姓名不返回，属企业微信侧策略，不影响发送 |

## 九、定时执行

### 先说一个必须澄清的模型：本插件不需要（也不能有）常驻服务

有这样一种猜测：「插件自己运行时才会执行代码，别的插件调用时它『没在运行』，所以应该让它一直挂着，
用定时任务检查它是否在运行、不在就重新拉起」。**这个模型与本插件的实际执行方式不符，这样做也做不到。**

TgtoDrive 的插件执行模型是**一次性进程**，有明确规定可查：

| 规定 | 出处 |
| --- | --- |
| 「`run(params, context)` 是同步函数，**每次运行都会启动新的 Python 进程**，模块全局变量不会跨任务保留」 | 开发指南《运行模型》 |
| 「每次运行是新进程，全局变量不跨任务保留」 | 协议清单《运行环境》 |
| 「插件自身**不能注册常驻服务、守护线程或后台定时循环**；**执行结束/超时会清理子进程**」 | 官方开发提示词 |
| 「插件内也不能注册常驻服务、守护线程或后台循环，**不要用 `sleep` 等下次执行**」 | 协议清单《定时执行》 |
| 「避免创建**脱离父进程的后台服务**」 | 开发指南《执行与持久化》 |

因此：

- **不存在「插件在运行中 / 没在运行」这个状态。** 别的插件调用
  `POST /api/toolbox/plugins/wecom-notify/run` 时，平台会**新起一个进程**执行本插件的
  `run()` —— 与你自己在界面点「发送测试消息」走的是**同一条路径、同一段代码**。
- **常驻服务在此模型下既不被允许、也不会生效**：进程在任务结束或超时时会被清理，
  拉起一个脱离父进程的后台服务等于自己制造一个平台会回收的孤儿进程。
- **定时任务做不到「保活」**：定时执行只是让平台在某个时刻又**新起一个进程**跑一次 `run()`，
  它跑完就结束，不会让插件「继续挂着」。用它来「检查服务是否在运行」没有对象可检查。

> **你自己的日志恰好证明了代码有被执行**：`微信通知发送成功` 这一行，是**轮询
> `wecom-notify` 的任务结果**得出的 —— 说明它的 `run()` 确实被「药丸论坛签到」调用并成功执行了。
> 也就是说，「别的插件调用时它的代码没跑」这一步并不成立。

#### 触发来源不参与判断（插件也拿不到）

还有一类相近的猜测：「参数是收到了，但这次 run 既不是用户点的、也不是定时任务触发的，
所以它只收参数、不发送」。这在本插件里不成立，有三层依据：

| 依据 | 说明 |
| --- | --- |
| **拿不到触发来源** | `run(params, context)` 只收到 `params` 与 `context`；规范明确「`context` **只有** `plugin_dir`、`data_dir` 两个键」。本插件也只读这两个键 —— 它**没有渠道知道**是谁触发的，因此不可能按来源区别处理 |
| **三种入口是同一个函数** | 界面点按钮、定时计划、其他插件调用，最终都是平台新起进程调用**同一个** `run(params, context)`（官方提示词：「主程序支持 cron 定时触发插件的同一个 `run(params, context)`」） |
| **代码里没有「收到但不发」的分支** | `execute()` 只在显式选择 `docs` / `config` / `history` / `test` 时走各自分支，**其余一律 `return self.do_send()`**；而且 `func` 的**缺省值就是 `send`**，即调用方连 `func` 都不传也会发送 |

#### 「被传入参数触发运行」是受支持的调用方式

还有一种更彻底的说法：「插件的运行方式**不支持**收到参数后触发运行」。这一点可以直接从接口定义排除：

- 运行接口的用途就是「**按插件 `inputs` 定义提交参数**，在服务使用的 Python 环境中
  **启动独立进程执行插件**」—— 它描述的是「提交参数 → 执行」，而不是「人类点按钮才执行」；
- 它在 OpenAPI 里以 `bearerAuth` 暴露，并明确「**Bearer 调用无需浏览器的 X-Toolbox-Request
  请求头**」，还给了调用步骤：「先从 `GET /api/toolbox/plugins` 读取 `inputs`，填入必填参数」
  —— 这本身就是写给**程序**（而不是浏览器界面）的调用说明；
- 唯一相关的禁令是「避免递归调用**自身**运行接口」，也就是说**调用别的**插件是被允许的。

**怎么自己判断「是不支持，还是支持但执行失败」**——看首个响应即可：

| 你收到 | 含义 |
| --- | --- |
| **HTTP 202 + `job_id`** | **触发已被接受，插件已在执行** —— 「不支持被其他插件触发」不成立；后续成败属于**执行阶段**的事，用任务查询接口看 |
| HTTP 404 | 目标插件未安装 / 未启用（或 `plugin_id` 写错） |
| HTTP 400 | 参数被拒：键未声明、`select` 取值不在 `options` 内 |
| HTTP 401 / 403 | 令牌无效或权限不足 |
| HTTP 503 | 队列已满，或目标插件已有未完成任务 |

> 你实例上的日志里出现过 `job_id=08070ecf…`，那就是本插件的运行接口返回的 **202 + job** ——
> 说明触发**已经被接受**、插件确实被执行了。如果这一步不被支持，你会拿不到 `job_id`，
> 而是直接收到上面的 404 / 400 / 403。

#### 怎么确认它这次真的执行并发出了

| 看哪里 | 能看到什么 |
| --- | --- |
| 结果明细的 `msgid` | 有 msgid ＝ 企业微信**已接收并受理**这条消息（`send` 成功时一定会返回） |
| 「我的插件 → 企业微信通知」最近运行记录 | 它**自己**的完整日志：`企业微信通知启动，执行功能：发送消息（供其他插件调用）`、实际收件人、`第 1/1 段发送成功，msgid=…`、投递校验结论 |
| 调用方结果页的 `delivery_ok` / `delivery_status` | 区分「已被受理」与「是否真的送达」 |

> 换句话说：**有 msgid 就是发出去了**。「发出去了但手机上没收到」属于投递问题
> （可见范围 / 微信插件设置），不是「没执行」。

**那「有时收不到」的真实原因是什么**（本仓库已逐一定位并修复）：

| 真实原因 | 表现 | 处理 |
| --- | --- | --- |
| 参数契约不符（键未声明 / `select` 取值不在选项内） | 调用方收到 **HTTP 400** | 双方清单要同步更新（本插件已把 `send`、`content`、`card_content` 声明进清单） |
| **`params` 不会与表单设置合并** | 凭据为空 → 任务提交成功但发不出去 | 本插件会从自己已保存的设置里补齐调用方没传的字段 |
| 拿不到任务 ID | 调用方只能显示「已受理」，看不到后台失败 | 任务 ID 容错提取 + 取不到时打印响应体 |
| **投递被可见范围拦住**（最常见） | 企业微信返回成功但**消息没到** | 本插件返回 `delivery_ok` / `invalid_users`，调用方据此判为「未投递」 |
| 同一插件已有未完成任务 | 新调用被拒或排队（见下） | 调用方重试 / 降级 |

**唯一与「它没在运行」沾边的真实限制**：平台规定「**同一插件只能有一个未完成任务**；
默认最多两个任务同时执行，队列数量有上限，满额时提示稍后重试」。
所以如果本插件的测试消息还没跑完（「发送测试消息」会**间隔 3 秒发两条**）时，又有别的插件来调用，
后者就可能被拒或被排队 —— 这属于**并发排队**，靠常驻服务解决不了，
正确做法是调用方在收到 503 时重试，或错开时间。

### 想要「定期确认它还活着」：用平台调度做心跳

如果你的目的是**及时发现链路坏掉**，正确做法是让平台调度器每天触发一次 `run()`，
用「**收到消息 = 链路正常**」来当心跳（这是「定时任务」在本平台上的正经用法）：

| 项目 | 建议值 |
| --- | --- |
| cron | `0 9 * * *`（每天 09:00，北京时间 Asia/Shanghai） |
| 运行参数（心跳，推荐） | `func=send`、`msgtype=text`、`touser=<你自己的 UserID>`、`content=【企业微信通知】每日自检：链路正常` |
| 运行参数（只自检凭据，不发消息） | `func=config` |
| timeout | `120`（插件已声明；计划沿用插件 timeout，无需单独设置） |

> 注意：计划在「上一轮仍在运行/排队、插件停用、队列已满」时会**跳过本次、不补跑**，
> 所以心跳哪天没收到，也可能是被跳过而不是链路坏了；把它当作**趋势观察**而不是严格告警更合适。

在「实用工具 → 我的插件 → 定时执行」新建计划，选择本插件即可。

插件内部不含任何定时循环，也不会 `sleep` 等下一次执行。

## 十二、安全与隐私

- Secret、EncodingAESKey、OpenAPI 令牌**不会**出现在运行日志、返回值与结果页中，仅显示「已填写（长度 N）」；企业 ID 与成员 ID 做掩码处理。
- 插件设置以**明文 JSON** 保存在服务器的插件目录，管理员可读取；更在意安全时请把「应用 Secret」留空，改用环境变量 `TGTO_WECOM_CORP_SECRET`。
- 唯一的写操作是插件数据目录下的 `token.json`（access_token 缓存）与 `history.json`（发送历史），**不写插件源码目录**。
- 不读取与需求无关的任何配置或凭据。

## 十三、实现与协议说明

- `access_token` 按「代理地址 + 企业 ID」缓存，提前 300 秒视为过期，避免频繁调用 `gettoken` 被限流。
- 命中 token 失效类错误（`40014` / `41001` / `42001`）时自动清缓存重取并重试**一次**。
- 分段时按行边界切分并逐字符累计字节数，不会切断 UTF-8 字符。
- 插件为同步 `run(params, context)`，不含异步、不含常驻线程；所有网络请求都在 `run` 内发起。
- 仅写入 `context["data_dir"]`，不触碰 `plugin_dir`。
- 消息类型收窄为 `text` / `news` 后，模板卡片相关的构造代码（键值列表解析、卡片字段截断、`card_action` 回退等）已一并移除；仅保留「把模板卡片 JSON 转成图文」的兼容路径。
