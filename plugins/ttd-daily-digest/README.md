# TTD 每日推送 · TgtoDrive 插件

每天定时把 **TgtoDrive 的媒体库动态**整成一条消息推给你 —— 今日入库了哪些资源、电影/剧集各新增多少、最近播放了什么、今天有哪些剧更新、播放趋势等，一条消息看完。

支持 **Telegram** 与 **企业微信（微信）** 两个渠道，可同时开、也可以只开一个；两个渠道各自独立发送、各自报告结果，一个失败不影响另一个。

- **插件 id**：`ttd-daily-digest`
- **版本**：`1.0.1`
- **作者**：`a2695154202`
- **入口**：`plugin.py`
- **超时**：180 秒（要读多个数据源并逐渠道发送，别设太小）
- **依赖**：仅 Python 标准库 + 容器已安装的 `requests`（不可用时自动回退 `urllib`）。**不安装任何依赖。**

> ⚠️ **插件不含任何内置凭据。** OpenAPI 令牌、Telegram 机器人、企业微信凭据全部来自 ttd 已有配置或你的填写，代码里不存在示例值。
>
> 💡 **微信渠道不重复填凭据**：它是通过调用 **「企业微信通知」插件（`wecom-notify`）** 来发的，企业 ID / Secret / 收件人等全部沿用对方插件里已保存的设置。你只要确保那个插件装好、启用、配好即可。

## 一、它能推什么

每个板块都可以在界面里单独开关，开了才去取数。**推荐全开**，一条消息也就几十行。

| 板块 | 输入开关 | 数据源 | 内容 |
| --- | --- | --- | --- |
| **媒体库总览** | `section_stats` | `GET /api/emby/dashboard` | 电影 / 剧集 / 单集总量、总播放次数、活跃用户数 |
| **今日新增** | `section_counts` | 由「最近入库」就地计算，**不额外请求** | 今日入库的电影数、剧集数、单集数 |
| **最近入库** | `section_added` | `GET /api/emby/latest?limit=N` | 最近入库的资源列表（名称 + 季集 + 年份） |
| **今日更新（追剧日历）** | `section_calendar` | `GET /api/media/calendar?days=N` | 今天更新的剧集（含评分、播出平台、类型） |
| **最近播放** | `section_recent` | `GET /api/emby/recent` | 最近播放记录 |
| **播放趋势** | `section_trend` | `GET /api/emby/trend?dimension=day\|hour` | 按天 / 按小时的播放次数趋势 |

> 「今日新增」是**派生板块**：它复用「最近入库」的数据本地统计，不额外发请求。所以开它必须同时开「最近入库」，否则会明确提示「依赖『最近入库』，但该板块没取到数据」并跳过 —— 不会静默少一块内容。

## 二、三种版式

| 版式（`msg_format`） | 长什么样 | 适合 |
| --- | --- | --- |
| **纯文本 `text`**（默认） | 用 `【标题】` 与 `· ` 项目符号，`──────────` 分隔 | **所有渠道都不错乱**，微信里也最稳（企业微信只保证文本消息不被转成「到企业微信查看」） |
| **Markdown `markdown`** | 用 `**加粗**` 与 `- ` 列表 | Telegram 里最漂亮；发微信时会**自动降级成纯文本**（去掉 `**` 等标记），因为微信插件收不到 Markdown |
| **精简 `compact`** | 只保留总量与今日新增等关键数字，砍掉所有列表 | 只想瞄一眼数字时 |

### 纯文本示例

```
【每日推送】10-14 21:00

TTD每日推送 · 10-14 21:00
──────────
【媒体库总览】
· 电影：6540 部
· 剧集：7301 部
· 单集：239343 集
· 总播放：113 次
· 活跃用户：1 人
──────────
【今日新增】
· 电影：0 部
· 剧集：5 部（新增 5 集）
──────────
【最近入库（10 条）】
· 美人余 · 第12集（2026）
· 无可替代 · S01E18（2026）
· 喜剧之王 · S01E20（2026）
──────────
【今日更新（8 部）】
· Slow Horses · S06E05（评分 8.1 · Apple TV · 犯罪/剧情/悬疑）
· 世界最强魔女，就此开始 · 第2集（评分 7.5 · 动画/喜剧/动作冒险）
```

## 三、界面功能（`func`）

界面**只有一页**，左侧 4 个分组卡片（通知渠道 / 推送板块 / 版式与条数 / 执行与接口），右侧是「快捷操作」卡片 + 「定时执行怎么配」说明卡片。

| 功能（`func`） | 说明 | 右侧快捷按钮 |
| --- | --- | --- |
| **正式推送一次（`digest`）** | 按当前设置采集并发送。定时执行也走这条 | ✅「正式推送一次」 |
| **只预览不发送（`preview`）** | 完整采集 + 渲染，但**一条都不发**，先把内容看一遍 | ✅「只预览不发送」 |
| **发送测试推送（`test`）** | 在正文顶部加一行测试横幅，然后**真实发送**，用来验证「渠道 + 网络 + 收件人」是否打通 | ✅「发送测试推送」（右上角主按钮） |
| **检查配置（`config`）** | 逐个探测 5 个数据源 + Telegram 机器人 + 微信插件 + 历史条数，一眼看出哪一步没通 | ✅ 在执行与接口卡片里 |
| **查看推送历史（`history`）** | 本地记录最近每次推送的时间、操作、各渠道结果 | ✅「查看推送历史」 |

> **右侧「发送测试推送」就是你要的测试按钮**：在左侧先选好「通知渠道」（Telegram / 微信），然后点它，消息会**真的推到你手机上**。

## 四、通知渠道怎么配

### Telegram

**不用填任何 Telegram 凭据** —— 插件直接读 ttd 已经配好的「通知机器人」（`GET /api/notify-bots`），取里面的 Bot Token 与推送目标（管理员用户 ID）。

| 参数 | 说明 |
| --- | --- |
| `notify_bot` | 用哪个机器人。`auto` = 优先选名字像「主机器人」的那个；也可以指定「列表第 N 个」（N 从 1 开始）。列表项即 ttd 里的机器人顺序 |

**网络代理**（这是最容易踩的地方）：

- ttd 接口地址通常是**内网**（如 `192.168.x.x:12366`），**必须直连**；
- 而 `api.telegram.org` 在多数中国大陆网络下**必须走代理**才能通。

插件把这两件事分开处理，Telegram 的连通方式按下列顺序**逐个尝试，成功即止**：

1. **ttd「网络代理」设置里生效的代理**（`GET /api/proxy_settings` 的 `effective_proxy`）—— 这是你自己配好、最可能能通的那个；
2. 机器人自带代理（如果 ttd 的机器人条目里带了 proxy 字段）；
3. 容器环境变量代理（`HTTPS_PROXY` / `HTTP_PROXY` 等，`proxy_mode=env` 时优先）；
4. 直连。

> ⚠️ 容器里的 `HTTP_PROXY` 往往是平台侧注入的**内部**代理，未必能出网到 Telegram（实测会返回 `502` 或直接超时）。**真正管用的是 ttd 自己配的代理**，所以插件把它排在第 1 位。若你从没在 ttd 里配过代理，而又需要代理才能访问 Telegram，结果页会直接提示你去配。

| 参数 | 说明 |
| --- | --- |
| `proxy_mode` | `off`（默认）= ttd 接口直连，Telegram 按上面的顺序择优；`env` = 明确优先使用容器环境变量代理 |
| `tgto_base_url` | ttd 地址。留空则读环境变量 `TGTO_OPENAPI_BASE_URL`，再回退 `http://127.0.0.1:12366` |
| `tgto_token` | OpenAPI 令牌。留空则读环境变量 `TGTO_OPENAPI_TOKEN` |

### 微信（企业微信）

**不在本插件里填企业微信凭据**，而是通过 OpenAPI 调用「企业微信通知」插件：

```
POST /api/toolbox/plugins/wecom-notify/run   （body 里带 envelope）
GET  /api/toolbox/plugins/jobs/{job_id}      （轮询取结果）
```

企业 ID / AgentId / Secret / 转发地址 / 收件人 / 代理模式**全部沿用 `wecom-notify` 里已保存的设置**，本插件只传「要发什么内容」。这样凭据只存在一处，改收件人不用改两遍。

| 参数 | 说明 |
| --- | --- |
| `wecom_plugin_id` | 要调用的微信通知插件 id，默认 `wecom-notify`。如果你装的是别的同类插件，改成它的 id |
| `wecom_touser` | 微信收件人（成员账号，`|` 分隔）。**留空 = 沿用 `wecom-notify` 里保存的收件人**（通常是 `@all`） |

**发送前的自检**（都会给出明确文案，不会含糊）：

- `wecom-notify` 没装 → 「没在 ttd 里找到插件『wecom-notify』—— 请确认已安装并启用」
- 装了但被停用 → 「目标插件已停用」
- 版本过旧、清单里没有 `envelope` 输入 → 「目标插件版本过旧，不支持 envelope，请更新」
- 队列忙（HTTP 409）→ **自动重试 3 次、每次间隔 3 秒**；仍忙则报「目标插件持续处于忙碌状态」

**投递结论**分三态，不会把「已投递」说成「不确认」：

| 状态 | 含义 | 结果页文案 |
| --- | --- | --- |
| `confirmed` | 对方按可见范围逐人核对过 | 已送达（收件人：…，成功 N/M 段） |
| `unknown` | 对方用的是**自建转发地址**，`user/list` 不可用，**校验做不了**，但 msgid 已拿到 | 已由「微信」发送（收件人：…）；该接口无法逐人核对投递情况，以微信端是否收到为准 |
| 有 `invalid_users` | 收件人不在应用可见范围，实际没投出去 | 已发送，但以下收件人不可见、实际未投递：… |

> 为什么 `unknown` 也要算成功：企业微信对「不可见收件人」**仍返回 `errcode=0` 与 msgid**（假成功）。`wecom-notify` 靠 `message/send` 返回的 `invalid_users` 做校验 —— 走自建转发地址时 `user/list` 会 404，逐人核对失效，此时只要 `invalid_users` 为空、msgid 到手，就按「已发出去」报告，并明确告诉你校验做不了。

| `history_days` | number | 30 | 本地推送历史保留天数（1–365） |

## 六、定时执行怎么配

本插件的清单里**不写 cron**（定时由 ttd 的「定时执行」界面统一管理）。在 ttd 里新建一个定时任务：

| 项 | 建议值 |
| --- | --- |
| **插件** | `TTD每日推送` |
| **cron 表达式** | `0 21 * * *` —— 每天 21:00（晚上入库基本完成后再推） |
| **执行功能 `func`** | `digest`（正式推送一次） |
| **通知渠道 `channels`** | 按你需要的勾：`tg` / `wecom` |
| **版式 `msg_format`** | `text`（通用）或 `markdown`（只发 TG 时更好看） |
| **超时** | 180 秒 |

> 想早上也推一次，就再加一条 `0 8 * * *` 的任务。插件是无状态的，跑两次不会串数据。

## 七、安装

1. 从插件市场安装，或下载 `dist/ttd-daily-digest.py` 单文件版在 ttd「我的插件 → 导入」里导入；
2. 打开插件，先在「执行与接口」里点**「检查配置与数据源连通性」**，确认 5 个数据源、Telegram 机器人、微信插件全绿；
3. 选好通知渠道，点右侧**「发送测试推送」**，确认手机能收到；
4. 最后去 ttd「定时执行」里按第六节配一条任务。

> **必须先装 `wecom-notify`**（微信渠道依赖它）。只推 Telegram 的话可以不装。

## 八、常见问题

**Q：点了测试按钮，Telegram 报「连接 Telegram 失败，已依次尝试 N 种方式」？**
A：网络问题，不是配置问题。结果页会逐个列出尝试过的代理地址。最常见的原因是 ttd 里没配代理而你的网络需要代理才能访问 Telegram —— 去 ttd「设置 → 网络代理」配好，或把 `proxy_mode` 设成 `env` 用容器的环境变量代理。容器里的 `HTTP_PROXY` 若是平台注入的内部代理，往往不能出网（会返回 502），此时得用 ttd 里配的那个。

**Q：微信显示「已发送，但该接口无法逐人核对投递情况」？**
A：这是成功的。`wecom-notify` 走的是自建转发地址，`user/list` 不可用所以无法逐人校验；只要 `invalid_users` 为空、拿到 msgid，就说明企业微信侧已受理。**以微信端是否真的收到为准。**

**Q：微信显示「收件人不在可见范围」？**
A：去企业微信管理后台 → 该应用 → 「可见范围」，把收件人加进去。

**Q：微信发出去但微信里收不到？**
A：这是企业微信的官方限制，不是插件问题。检查三处：① 应用可见范围是否含收件人；② 应用是否勾了「**在微工作台中始终进入主页**」（勾了之后微信端**只能收到文本消息**）—— 这一项最容易被忽略，把 `msg_format` 设成 `text` 可规避；③ 微信 → 通讯录 → 本企业 → 微信插件 → 右上角 → 设置 → 「接收应用消息」是否打开。

**Q：`config` 里某个数据源报 404 / 500？**
A：那个接口在你的 ttd 版本里可能不支持，关掉对应板块即可（`section_*` 开关）。其余板块不受影响。

**Q：内容里出现 `S00E80` 这种奇怪编号？**
A：数据源把动漫的 `season_number` 记成了 0。插件已处理：季号为 `0` / 空时只显示「第 80 集」，不会出现 `S00`。

**Q：能只推「今日新增」一项吗？**
A：可以。把 `section_added` + `section_counts` 打开，其它板块全关，`msg_format` 选 `compact`。

**Q：推送历史存在哪？**
A：插件数据目录下的 `history.json`（`context["data_dir"]`），最多 400 条，按 `history_days` 过滤旧记录。删掉它等于清空历史。

## 九、安全与隐私

- **不内置任何凭据**；OpenAPI 令牌、机器人 Token、企业微信 Secret 全部来自 ttd 已有配置或你的填写，且**任何网络错误与日志输出都会先脱敏**（`corpsecret` / `corpid` / `access_token` / `secret` / `token` 等键值，以及 URL 路径里的 `bot<id>:<token>`），不会把凭据写进运行日志。
- 微信渠道**不复制**凭据：企业内部 ID、Secret、收件人只存在于 `wecom-notify` 一处。
- 插件只读 ttd 的数据接口（`/api/emby/*`、`/api/media/calendar`、`/api/notify-bots`、`/api/proxy_settings`），除发送通知外**不修改任何 ttd 数据**。
- 唯一的本地写入是 `history.json`（推送记录），不含消息正文中的敏感信息。
