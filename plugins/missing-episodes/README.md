# 剧集缺集检测与补齐（未开发完成）· TgtoDrive 插件

> 🚧 **未开发完成，仅供测试** —— 功能、参数与结果格式都可能变动，请勿长期依赖。

读取媒体库里**已有哪些集**，与 TMDB 上**应该有哪些集**求差集，找出缺集；
再按你配置的搜索源去找缺失资源，并按选定动作补齐。

- **插件 id**：`missing-episodes`
- **版本**：`1.0.0`
- **入口**：`plugin.py`
- **超时**：1800 秒（媒体库较大时检测会用到；可用「单次检测上限」控制）
- **依赖**：标准库 + 容器已装的 `requests`
- **参考实现**：MoviePilot 的
  [`getmissingepisodes`](https://github.com/andyxu8023/MoviePilot-Plugins/tree/main/plugins.v3/getmissingepisodes)
  （「用媒体服务器的实际季集与 TMDB 的应有季集做集合差集得缺失集，再按配置记录/订阅/忽略」的思路一致；
  差别在于本插件按 TgtoDrive 的接口能力落地，见下文「为什么必须直连 Emby」）

## 一、三个数据源

| 用途 | 来源 | 说明 |
| --- | --- | --- |
| **本地已有季集** | **Emby 直连** | 见下方「为什么必须直连 Emby」 |
| **应有季集** | TgtoDrive 的 TMDB 代理 **或本插件直连 TMDB** | 二选一（默认「自动」）：走代理用 `GET /api/media/details/tmdb/tv/{id}` 与 `/season/{n}`；直连用 `GET /tv/{id}` 与 `/tv/{id}/season/{n}`。**直连不受「详情页完整季集模式」限制** —— 见下节 |
| **缺失资源** | TgtoDrive 内置资源检索 / 你自建的盘搜（PanSou） | 用哪个由你选，也可以两者都查 |

### 「应有季集」的两个数据源：TgtoDrive 代理 vs 直连 TMDB

关键在一个 **ttd 侧的限制**：

> TgtoDrive 的 `/api/media/details/tmdb/tv/{id}/season/{n}` 在官方规范里写明
> 「**只有当前详情配置支持完整季集模式时可用**」。

详情页没开这个模式时，该接口对**每一季**都返回：

```json
HTTP 409
{"code":"TMDB_READONLY_MODE_INACTIVE","error":"当前详情页不使用完整 TMDB 季集模式"}
```

而缺集检测完全依赖「每一季应该有哪些集」—— 该接口一不可用，整条链路就**没有数据源**。
如果这个模式在你的 ttd 里找不到开关，**直接让本插件自己连 TMDB** 最省事：

| 数据源 | 怎么用 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **TgtoDrive 详情代理** | 默认；数据源选「TgtoDrive 详情代理」 | 不用额外凭据；复用 ttd 的网络与缓存 | 受「完整季集模式」限制，未开启时返回 409 |
| **直连 TMDB（推荐）** | 填 `TMDB API Key`，数据源选「自动」或「直连 TMDB」 | 不受那个模式限制；可自选接口地址与代理 | 需自己申请一个 TMDB API Key；容器要能出网 |

**数据源选「自动」（默认）时**：填了 TMDB API Key 就**直连**，没填就**走 TgtoDrive 代理**。

#### 申请 TMDB API Key

1. 注册并登录 [themoviedb.org](https://www.themoviedb.org/)；
2. 右上角头像 → **设置 → API**；
3. 申请 **API Key（v3 auth）**，把那串 Key 填进本插件的「TMDB API Key」；
4. 保存后点「**测试连接**」，看 **TMDB 数据源** 与 **TMDB 季集详情（关键）** 两行是否变 ✔。

#### 出网与代理

直连是**本插件自己发的请求**，不经过 TgtoDrive，所以容器必须能访问 `api.themoviedb.org`。
出不了网时按下面顺序处理（与插件里的「TMDB 代理策略」一一对应）：

| 策略 | 行为 |
| --- | --- |
| **自动**（默认） | 依次尝试：**TgtoDrive 的网络代理设置** → 容器环境变量 `HTTPS_PROXY` → 直连 |
| 只用容器环境变量代理 | 只用 `HTTPS_PROXY` / `HTTP_PROXY` |
| 不使用代理 | 直连 |

> ⚠️ 容器里的 `HTTP_PROXY` / `HTTPS_PROXY` 往往是**平台侧的内部代理**，拿它出网到公网会被送到错处
> （实测返回 `502 Bad Gateway`）。所以「自动」**优先用 TgtoDrive 自己配的网络代理**。
> 实在不行就在「**TMDB 代理地址**」里手填一个可用代理 —— 它优先级最高，且**只对 TMDB 生效**
> （不影响 TgtoDrive / Emby / 盘搜）。

**不会重复打扰 TMDB**：只有「代理 / 网关层」错误码（407 / 502 / 503 / 504 / 52x）才会换下一个代理；
TMDB 自身的响应（`401` Key 无效、`404` 没有这一季、`429` 限流…）**立即停止**。

走 TgtoDrive 代理时，TMDB 请求由 ttd 发出，本插件的代理设置不参与。


### 参数从哪来：优先读 TgtoDrive 自己的配置

本插件**不另立一套配置** —— 能用 TgtoDrive 里已经配好的，就直接读它的：

| 参数 | 来源 | 说明 |
| --- | --- | --- |
| **转存目标网盘** | `GET /api/media/settings` → `target_provider` | 表单「目标网盘」留空时自动用它，作为转存 / 离线接口的 `provider` |
| **转存目录** | 同上 → `media_transfer_targets` | **只读出来展示**（「查看生效配置」里可见）；由 TgtoDrive 自己应用，本插件**不会**把它当网盘标识发出去 |
| **点数上限** | 同上 → `max_points` | 转存时一并带上（并置 `enforce_points_limit`），避免本插件再维护一份 |
| **可用资源来源** | `GET /api/media/providers` | 只读出来展示（「测试连接」会列出），要限定就把它填进「资源来源」 |
| **能力清单** | `GET /api/media/capabilities` | 当前支持的检索 / 转存 / 离线能力 |
| **RE0** | `GET /api/re0/status` | **RE0 是 TgtoDrive 自己集成的服务**，接口说明原文即「判断**资源检索、解锁及转存**等 RE0 功能是否可用」。凭据与授权由 TgtoDrive 保管，本插件**只读状态**，不需要你在这里填任何 RE0 信息；未授权时「测试连接」会提示你去「影视发现 → RE0」完成授权 |
| **Emby** | `GET /api/media/settings` → `media_emby` | 表单留空时复用（见下节） |
| **盘搜（PanSou）地址** | ⚠️ **TgtoDrive 里没有它的配置项** | 规范里没有 `pansou` 字样，`/api/media/settings` 只有 8 个字段（`target_provider` / `media_transfer_targets` / `max_points` / `media_emby` / `guanying` / `check_interval_minutes` / `emby_missing_scan_interval_minutes` / `ranking_virtual_libraries`）。所以要用**自建盘搜**时需要在插件里填一次地址；**如果你指的是 TgtoDrive 内置的资源检索**（它的可用来源里就含 RE0），那它已经全程走 TgtoDrive 的配置，不用额外填 |

**优先级**：表单里填了就用表单（临时覆盖），**留空就用 TgtoDrive 的配置**。

**读不到时的行为**：三个配置接口（settings / providers / re0）**各自独立降级** ——
失败的那项只记一条警告并留空，**不会中断检测**，也不会用猜测值填充。
`providers` 的原始响应会写进运行日志，便于你在「资源来源」里手填标识。

> 本插件对这些配置**只读不改**：不写 TgtoDrive 的设置，也不碰你的网盘账号授权。

### 为什么必须直连 Emby

TgtoDrive 的 OpenAPI **没有**「取某部剧的本地集号清单」的接口：

- `/api/emby/dashboard` 只给电影 / 剧集 / 单集**总量**；
- `/api/emby/latest` 只给**最近入库**（名称 + 季集），不是完整清单；
- `/api/emby/libraries` 只给媒体库列表与数量；
- `/api/media/emby/cards` 只给「某影视条目是否已入库」，不是逐集清单。

MoviePilot 那个插件靠 `MediaServerChain.episodes()` 拿「本地已有集」，这套能力在 TgtoDrive 的
公开接口里对应不到，所以本插件让你填 **Emby 地址 + API Key** 直连读取（只读）。
在「TgtoDrive → 影视发现」里已经配过 Emby 的，本插件会自动复用那份配置 —— 表单留空即可。

填网页入口（形如 `http://host:8096/emby`）也可以，插件会自动去掉 `/emby` 这一层。

## 三、能补哪些情况：集 / 季 / 整剧

| 场景 | 是否覆盖 | 条件 |
| --- | --- | --- |
| **某一季里的部分集缺失** | ✅ 默认就覆盖 | 例：S01 本地有 E1、E2，TMDB 有 E1–E4 → 报「S01 缺 E03、E04」 |
| **整季缺失**（本地该季一集都没有） | ✅ 需关掉「只检查本地已有季的缺失」 | 关闭后列为「整季缺失」；开启时跳过 |
| **整剧未入库**（本地一集都没有） | ✅ 同上 | 关闭后该剧的每一季都列为「整季缺失」 |
| **电影 / 音乐 / 其它类别** | ❌ **按设计不生效** | 见下节 |

> **「跳过」不会静默发生**：默认设置下被跳过的整剧会
> ① 在日志里写明原因，② 在结果页出现「整剧未入库跳过」指标卡与一条说明，
> 并提示「想连整季 / 整剧一起补齐就关掉那个开关」。

搜索关键词取**剧名**（会自动去掉 `S01` / `第X季` / 年份括号等噪声），
所以搜到的是整部剧或整季的资源包，里面通常包含缺失的那些集；
走 TgtoDrive 内置检索时还会把 `season` / `episode` 一并传给接口。

## 四、只处理剧集类媒体库（电影 / 音乐不生效）

**本插件只处理剧集。** 电影、音乐、音乐视频、有声书、书籍、家庭视频、合集、照片、游戏、
播放列表这些类别的媒体库会被**按 Emby 的 `CollectionType` 自动排除**：

- 默认（媒体库 id 留空）时只扫描剧集类库（`tvshows` / `mixed` / 未标注类型）；
- 被排除的库会**写进运行日志与结果页**（例：`已按媒体库类型排除 3 个非剧集库：电影[movies]、音乐[music]、音乐视频[musicvideos]`）；
- 如果你手动把「媒体库 id」填成电影库 / 音乐库，插件会**明确报错并列出 Emby 里现有的库**，
  而不是静默返回 0 条（那样会让人以为插件坏了）；
- 「测试连接」里也有一项「**媒体库筛选**」，会说明将扫描几个剧集库、排除了哪些；
- 读不到媒体库列表时**降级**为「按条目类型兜底」（只查 `IncludeItemTypes=Series`），
  仅记警告，不会因此失败。

> 为什么不仅要靠 `IncludeItemTypes=Series`：那条查询在实际执行时确实能挡住非剧集条目，
> 但「你指定的库不是剧集库」这种情况会表现为**静默 0 条**，看不出原因。
> 显式按库类型排除 + 把排除项写进日志与结果页，才能让「按设计不生效」和「配置错了」分得清。

## 五、怎么判断「缺失」

核心是**集合差集**，没有数值阈值 —— 与参考插件一致：

```text
某季缺失集 = TMDB 该季的应有集号  −  Emby 里该季已有的集号
```

默认行为（建议保持）：

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| **只统计已播出的集** | 开 | TMDB 上「尚未开播」的集不计入应有集数，避免把未更新的剧当成缺集。没有播出日期的集也按未开播处理 |
| **只检查「本地已有季」的缺失** | 开 | 本地一集都没有的季会被跳过，避免把「整季没下载」也算成缺集。关掉后这些季会列为「整季缺失」 |
| **包含特别季 S00** | 关 | S00（特别篇 / 花絮）通常不是正片 |
| **忽略关键词** | 空 | 剧名含这些词就跳过，例如 `预告, 花絮, 合集` |

「单次检测上限」默认 **50 部**（按剧名排序从前往后取），防止媒体库很大时超时。
配合「我的插件 → 定时执行」分批跑即可全量覆盖。
> 整库大于该上限时，本插件会**按偏移轮转**（进度存在 `data_dir/scan_cursor.json`）：
> 每次从上次结束的位置往后接着扫，多跑几次即可覆盖全库 —— 不会每次都只看开头那几部。

### ⚠️ 「无法判定」是第三种结果，不等于「没有缺失」

一部剧检测完可能会有**三种**结局，请务必区分：

| 结果 | 含义 |
| --- | --- |
| **有缺失** | 比出了具体缺的集 → 出现在缺失明细表里 |
| **无缺失** | 每个季都比对成功，且集号齐全 |
| **⚠️ 无法判定** | 某些季的「应有集数」**没读成** → 既不算缺失、也不算完整 |

**「无法判定」必须当成「不知道」，而不是「完整」。** 它常见于两种情况：

- **「季集详情」数据源不可用** —— 走 TgtoDrive 代理时，规范对
  `/api/media/details/tmdb/tv/{id}/season/{n}` 的说明原文是
  「**只有当前详情配置支持完整季集模式时可用**」；未开启时对所有季返回
  `HTTP 409 TMDB_READONLY_MODE_INACTIVE`。
  这个数据源不通时，插件拿不到「应该有哪些集」，于是会把**每一部剧**都判为「无法判定」
  （而不是谎报「无缺失」）。点「测试连接」可以看到
  「**TMDB 数据源**」与「**TMDB 季集详情（关键）**」两项的结论。
  **解法**：到「② TMDB 设置」填上 TMDB API Key 改用直连（推荐），或在 TgtoDrive 里开启该模式。
- 个别季临时请求失败（网络抖动 / 5xx）—— 只影响该季，同剧其它季照常判定，
  失败原因会写进明细表的「说明」列。

## 六、补齐：搜索源与动作

### 搜索源（用哪个由你选）

| 取值 | 说明 |
| --- | --- |
| `both`（默认） | 两者都查，结果合并后挑一个候选 |
| `pansou` | 只查**盘搜（PanSou）** —— 响应结构是公开文档化的，候选解析完整 |
| `builtin` | 只查 **TgtoDrive 内置资源检索**（`/api/media/resources/search`）—— 省一个外部服务 |

> ⚠️ **关于内置资源检索**：该接口在 OpenAPI 规范里**没有响应 schema**（标记 `inferred`）。
> 本插件用一个通用策略识别候选（找同时带链接与来源信息的条目），并把**原始响应写进运行日志**。
> 如果它返回的结构与预期不同，请对照日志与「我的插件 → 影视发现」页面确认字段，
> 以便后续版本精确对接。盘搜那条路不受此影响。

盘搜（PanSou）是本插件默认的外部搜索源，官方默认端口 `8888`，默认不启用鉴权；
启用鉴权时在「盘搜令牌」里填 JWT Token。可用网盘类型见
[PanSou 文档](https://github.com/fish2018/pansou)：
`baidu` `aliyun` `quark` `guangya` `tianyi` `uc` `mobile` `115` `pikpak` `xunlei` `123` `magnet` `ed2k`。

### 补齐按「季」逐条处理

一部剧缺多个季时，**每个缺失季各自搜索、各自挑候选、各自执行动作**，结果表按季展开成多行。
（早期版本整部剧只挑一个候选，缺 S01/S02/S03 时只会补到其中一个季。）
「单次补齐上限」限制的是**部数**，季数不受限。

搜索关键词：

- **只缺一季** → `剧名 S02`（带上季号，减少「想补 S02 却抓到 S01 包」）；
- **缺多季** → 只用剧名（一次拿到整包更省事）。

挑选候选的优先级：**磁力 / 电驴**（可直接离线下载）→ 在「盘搜网盘类型」白名单内的网盘 →
其它；同一档内**按资源更新时间从新到旧**（越旧越可能失效）。

> 「候选」里如果只有网盘链接而动作选了「提交离线下载」，那一季会被标为**跳过**并说明原因，
> 结果页也会汇总「有 N 个季没有可执行的候选」—— 不会静默什么也不做。

### 补齐动作

| 取值 | 行为 | 是否写数据 |
| --- | --- | --- |
| `record`（默认） | 只把候选链接与提取码写进结果页和日志 | **否** |
| `transfer` | 调 TgtoDrive 转存接口把分享链接存进你的网盘 | **是**（会真实写网盘，可能消耗会员点数） |
| `offline` | 只对磁力 / 电驴候选有效，调离线下载接口创建任务 | **是** |

**预览模式（dry-run）默认开启**：任何动作都只打印「将要执行什么」，不会真的写入。
请先按默认配置跑一次，核对结果页里的候选链接，确认无误后再关掉预览模式。

「单次补齐上限」默认 **1 部**，先小步验证；确认稳定后再调大。

挑选候选的优先级：**磁力 / 电驴**（可离线下载）→ 在「盘搜网盘类型」白名单内的网盘 → 其它。

## 七、快速上手

1. 打开插件，在「① 连接设置」填 **OpenAPI 令牌** 与 **Emby 地址 / API Key**
   （TgtoDrive 里已配过 Emby 的话，Emby 两项可以留空）；
2. 点「**① 测试连接**」，确认四项都是 ✔ —— 尤其别跳过 **TMDB 季集详情（关键）** 这一项；
3. 点「**② 检查缺失（只读）**」，看结果页的缺失明细；
4. 需要补齐时，在「④ 补齐设置」里选搜索源与动作（**先保持默认**），点「**③ 检测并补齐**」；
5. 核对结果页里的候选链接 → 关掉「预览模式」→ 再跑一次，才会真正执行。

> 想确认插件到底用了哪些值（表单值 / TgtoDrive 兜底值 / 内置默认值），随时点「**查看生效配置**」。

## 九、排错

| 现象 | 原因与处理 |
| --- | --- |
| 「未配置 Emby 地址或 API Key」 | 本插件需要直连 Emby 才能读到本地季集（TgtoDrive 接口没提供该数据）。在「① 连接设置」填写，或在 TgtoDrive 影视设置里配好 Emby 后把插件表单两项留空 |
| Emby 测试报 HTTP 401 | API Key 无效或权限不足 —— 到 Emby 后台「设置 → API 密钥」重新创建 |
| 「Emby 条目里没有 TMDB id」 | 该剧在 Emby 里缺少 TMDB 元数据（`ProviderIds.Tmdb`）。到 Emby 里手动识别一次，或跳过该条目 |
| 「TMDB 详情里没有解析到季列表」 | TMDB 详情接口的字段可能与预期不同（规范标记 `inferred`）。原始响应片段会写进运行日志，请对照后反馈 |
| 补齐明细里某行显示「**跳过**」 | 候选类型与所选动作不匹配（离线下载只接受磁力 / 电驴），或该季没搜到资源。换「转存到网盘」动作，或放宽网盘类型白名单 |
| 某季明明还没播出却没被报缺失 | 这是**预期行为**：未开播的集不计入应有集数；整季都没播出时该季直接跳过（日志会写「还没有任何已播出的集，跳过该季」）。想连未播出的也算，请关掉「只统计已播出的集」 |
| 报错「没有找到可扫描的**剧集类**媒体库」 | 你手动填的「媒体库 id」里没有剧集库（可能填成了电影库 / 音乐库）。清空该字段即自动扫描全部剧集库 |
| 某部剧明明没入库，却没出现在缺失列表里 | 默认开启了「只检查本地已有季的缺失」—— 本地一集都没有的剧会被跳过。日志与结果页会**点名说明**这一点；想连整剧一起补齐就关掉那个开关 |
| **报告 RE0 未授权** | RE0 是 TgtoDrive 集成的服务，本插件只读它的状态。到 TgtoDrive 的「影视发现 → RE0」完成主账号授权即可；未授权时走 RE0 的检索 / 解锁 / 转存会不可用 |
| 「可用资源来源」显示「未能识别」 | `/api/media/providers` 在规范里没有响应 schema。原始响应已写进运行日志，可据此把来源标识手填到「补齐设置 → 资源来源」；不填也能用（由 TgtoDrive 决定来源） |
| 转存目标不对 | 表单「目标网盘」填了就会**覆盖** TgtoDrive 的 `target_provider`。清空它即使用 TgtoDrive 里配的转存目标。注意这里填的是**网盘标识**（`provider`），不是目录路径；TgtoDrive 的转存目录（`media_transfer_targets`）由它自己应用，本插件不会把它当网盘标识发出去 |
| 补齐只处理了一部分 / 提示「总时间预算用尽」 | 缺集很多时，一次运行可能跑不完。本插件按时间预算（整轮 1650 秒）到点收工并说明剩余量，**多跑几次**即可；也可以调小「单次检测上限」分批处理 |
| 「**整个结果页看不到**」/ 提示已截断 | 平台的 `table` 组件最多 200 行。缺失明细超过 200 行时本插件会自动截断并**在结果页说明**，完整数量以 `missing_total` / `filled_total` 与运行日志为准 |
| 检测到大量「缺集」 | 检查「只统计已播出的集」是否被关掉；以及该剧的 TMDB 元数据是否正确 |
| 检测很慢 | 调小「单次检测上限」，或限定「媒体库 id」；每部剧都要读 TMDB 的季详情，本身有网络开销 |
| 搜不到候选 | ① 看运行日志里内置检索的**原始响应**；② 盘搜换个更短的关键词（本插件已自动去掉季/集标注）；③ 检查盘搜地址与网盘类型白名单 |
| 补齐没生效 | 默认是**预览模式**，只打印不执行；确认后再关掉它 |
| 内置检索返回空 | 该接口无响应 schema，识别策略是通用启发式；优先用盘搜，或把日志里的响应结构反馈过来 |
| **每一部剧都报「无法判定」** | 「季集详情」数据源不可用 —— 先点「测试连接」看「**TMDB 数据源**」与「**TMDB 季集详情（关键）**」两项。**最省事的解法**：到「② TMDB 设置」填上 TMDB API Key，数据源选「直连 TMDB」（或保持「自动」），直连不受 ttd「详情页完整季集模式」限制；也可以改为在 TgtoDrive 里开启该模式 |
| **「无法判定」是什么** | 见第五节：某些季的「应有集数」没读成。它**不等于「没有缺失」**，请不要据此认为那些剧是完整的 |
| 日志里只有「响应结构：…{键名}」看不到内容 | 这是**有意为之**：实测详情响应按字母序排键，截取前 N 字会把最关键的字段名（如 `number_of_seasons`）切掉，所以改成输出**键名结构**，体积小且信息正好够排查 |

## 十、实现与协议说明

- 同步 `run(params, context)`；**模块导入阶段不发任何网络请求**，全部请求都在 `run` 内；
- 每次请求都设 `timeout`、`allow_redirects=False`（`urllib` 回退路径也用了拒绝重定向的 opener），并检查状态码；
- **凭据一律脱敏**：判定按归一化键名 + 片段（`secret` / `token` / `password` / `apikey` …），
  明文不会出现在运行日志、结果页或返回值中；Emby 的 API Key 走请求头而不是查询串，避免落进日志；
  脱敏保留位数不超过凭据原长的 1/3（短凭据不会被「脱」成几乎明文）；
- **只写 `context["data_dir"]`**（扫描游标 `scan_cursor.json`），不触碰 `plugin_dir`；
- **平台会把清单默认值填齐**：所以「TgtoDrive 地址」等于清单默认值时会被视为**未填写**，
  以便容器环境变量 `TGTO_OPENAPI_BASE_URL` 生效（这是本项目踩过的坑，已在注释中说明）；
- 调 TgtoDrive 接口时不传 `save_settings`，不改动用户的任何设置；
- **两种时间预算**：检测 1500 秒、整轮（含补齐）1650 秒，到点带结果收工，避免撞上插件超时后整轮白跑；
- 结果体积受运行器限制（≤1 MiB），表格最多 200 行（超出自动截断并说明），日志超过 2000 行丢最旧的。

## 十一、已知限制（v1.0.0）

1. **需要 Emby 直连**：TgtoDrive 没有提供本地集号清单接口，这是唯一可行的读法。
2. **「应有季集」依赖「季集详情」接口**：该接口在规范里写明「只有当前详情配置支持完整季集模式时
   可用」。不可用时本插件会把受影响剧集判为**「无法判定」**（绝不谎报「无缺失」），
   并在「测试连接」里明确报出来。
3. **季号的来源**：优先取详情响应里的 `seasons` 列表；该字段缺失时用 `number_of_seasons`
   推断 `1..N`（TMDB 语义不含特别篇）；并**并入 Emby 本地已有的季**，避免因 TMDB 与本地
   分季方式不同而漏检。若 TMDB 侧某季确实没有数据，该季会被安静跳过（日志有 INFO）。
4. **TgtoDrive 内置资源检索的响应结构未经真实环境验证**，候选识别是通用启发式；
   盘搜（PanSou）那条路是按其公开文档实现的，不受此影响。
5. **转存 / 离线下载的请求字段**取自规范中 `inferred` 级别的请求体字段列表，
   可能与真实接口有差异；因此默认走预览模式，第一次实际执行请留意返回信息。
6. 不支持电影（本插件只处理 `Series`）；不支持跨库合并（同一部剧在多个库里有副本时按各自库分别统计）。
